# llm_services

FastAPI gateway that routes LLM requests (chat, embeddings, rerank) to providers such as
OpenAI, Anthropic, Azure OpenAI, Bedrock and vLLM. It authenticates callers with JWTs,
enforces tenant/user authorization, and keeps provider credentials in Vault.

This guide takes a new developer from a clean checkout to a working chat call.
Commands are PowerShell (Windows); Linux/macOS equivalents are noted where they differ.

## What you need

| Requirement | Notes |
|---|---|
| Python 3.12+ | The repo pins `3.12` in `.python-version`. Use the project `.venv`, not a bare `python` that may be older. |
| Docker Desktop (or Docker Engine + Compose v2) | Runs PostgreSQL, Redis, Vault and the API. Nothing else is installed on the host. |
| `uv` (optional) | `uv sync` creates `.venv`. Plain `python -m venv .venv` + `pip install -e .` also works. |

## 1. Install dependencies

```powershell
cd llm_services
uv sync
.venv\Scripts\activate
```

## 2. Create your `.env`

```powershell
Copy-Item .env.example .env        # Linux/macOS: cp .env.example .env
```

`.env` holds secrets and is git-ignored. Never commit it. The example ships placeholder
secrets (an all-zero `ENCRYPTION_MASTER_KEY` and a `change-me` `JWT_SECRET_KEY`), so replace
those two with fresh values. This snippet edits `.env` in place:

```powershell
@'
import base64, pathlib, re, secrets
p = pathlib.Path(".env")
t = p.read_text(encoding="utf-8")
t = re.sub(r"(?m)^ENCRYPTION_MASTER_KEY=.*$", "ENCRYPTION_MASTER_KEY=" + base64.b64encode(secrets.token_bytes(32)).decode(), t)
t = re.sub(r"(?m)^JWT_SECRET_KEY=.*$", "JWT_SECRET_KEY=" + secrets.token_hex(32), t)
p.write_text(t, encoding="utf-8")
'@ | python -
```

On Linux/macOS, put the same Python between `python - <<'EOF'` and `EOF`.

Where each value comes from:

| Variable(s) | What to do |
|---|---|
| `ENCRYPTION_MASTER_KEY` | Generated by the snippet above (32 random bytes, base64). Required at startup. Keep it private and do not change it once you have stored secrets with `SECRET_BACKEND=aes_gcm`, because they become unreadable. |
| `JWT_SECRET_KEY` | Generated by the snippet (64 hex chars; the API rejects keys shorter than 32 bytes). It signs and verifies access tokens, and `llm_token_manager` must use the same value (step 6). To generate one by hand: `python -c "import secrets; print(secrets.token_hex(32))"`. |
| `JWT_ISSUER`, `JWT_AUDIENCE` | Leave the defaults. Tokens must carry exactly these `iss`/`aud` values or the API returns 401. If a real identity service issues your tokens, set them to match what it emits. |
| `SECRET_BACKEND` | Keep `vault`. The management API stores provider credentials in Vault (step 5d). `environment` only works if you place provider keys in `.env` and skip the credential field. |
| `POSTGRES_*`, `REDIS_*`, `VAULT_*`, `DATABASE_URL`, `REDIS_URL` | Local-only defaults for a disposable stack, consistent with each other. Leave them, or change a password everywhere it appears (variable plus the URL that embeds it). Postgres keeps the password it was first initialised with, so after changing passwords on a stack that has already started, run `python -m infrastructure reset --confirm-delete-volumes` (this deletes all local data). |
| `VAULT_ADMIN_*`, `LOCAL_DASHBOARD_JWT_USER_ID`, `LOCAL_DASHBOARD_JWT_ROLE`, `JWT_ACCESS_TOKEN_EXPIRE_HOURS` | Not in the example. `python -m infrastructure init` generates them (step 3). |
| Provider API keys (`OPENAI_API_KEY` and similar) | Not needed for this guide. You send the key in the deployment request (step 5d) and it is stored in Vault. Create one in the provider's console, for example https://platform.openai.com/api-keys for OpenAI. They are only read from `.env` when `SECRET_BACKEND=environment`. |
| AWS, Azure, GCP credentials, `SENTRY_DSN` | Optional, and only for Bedrock, Azure OpenAI, Vertex or Sentry. |

## 3. Start the local stack (one command)

```powershell
python -m infrastructure check    # read-only preflight: Docker, ports, .env, schema
python -m infrastructure init     # adds missing .env values (JWT_ISSUER, JWT_AUDIENCE, secrets)
python -m infrastructure start    # Postgres + Redis + Vault, applies the schema, builds and starts the API
python -m infrastructure verify   # pg_isready, redis ping, vault status
```

- `init` only appends missing keys. It never overwrites values you already set. After step 2,
  `check` warns that it will generate a few values (`VAULT_ADMIN_*`, `LOCAL_DASHBOARD_JWT_*`,
  `JWT_ACCESS_TOKEN_EXPIRE_HOURS`); that is expected.
- `start` runs the preflight itself, stops anything already holding ports 5432, 6379 or
  8200, and reports what it stopped.
- The API runs in the `llm_app` container. Check it at http://localhost:8000/health and
  browse http://localhost:8000/docs (Swagger).
- Other commands: `status`, `stop`, `restart`, `connection-info`,
  `connect postgres`, `connect redis`, `reset --confirm-delete-volumes` (deletes all local data).
  See [infrastructure/README.md](infrastructure/README.md) for details.

After changing backend code, rebuild the image, because `restart` reuses the old one:

```powershell
docker compose up -d --build app
```

## 4. Get an access token

This service only verifies tokens; it has no login endpoint. For local work the
infrastructure tool mints one:

```powershell
python -m infrastructure connection-info
```

Copy `DASHBOARD_JWT_TOKEN` from the output. Properties of the local token:

- Signed with `JWT_SECRET_KEY` from `.env`, issuer `JWT_ISSUER`, audience `JWT_AUDIENCE`.
- Lives `JWT_ACCESS_TOKEN_EXPIRE_HOURS` hours (default 1). The API rejects tokens that live
  longer than `JWT_MAX_TOKEN_AGE_SECONDS` (3600), so keep that setting at 1 hour or less.
  Rerun `connection-info` for a fresh token when it expires.
- Identity comes from `LOCAL_DASHBOARD_JWT_ROLE` (`developer`, `operator`, `admin`, `owner`)
  and `LOCAL_DASHBOARD_JWT_USER_ID` in `.env`. Use `owner` or `admin` to call management
  endpoints. Change either value and rerun `connection-info` to get a token with the new
  identity.

Swagger: click **Authorize** and paste the token without the `Bearer ` prefix.

## 5. Seed data and make a first chat call

A valid token is not enough for inference. The caller also needs a user, a tenant, a tenant
membership, a deployment (which stores the provider credential in Vault) and an entitlement.
Records that store a creator (`created_by_user_id`) require the token's user to exist, so
create your user first and then switch the token to that user.

Set up a helper (replace the token):

```powershell
$env:TOKEN = "<DASHBOARD_JWT_TOKEN>"
$Base = "http://localhost:8000"
function Api($Method, $Path, $Body = $null, $Extra = @{}) {
  $h = @{ Authorization = "Bearer $env:TOKEN" } + $Extra
  $args = @{ Method = $Method; Uri = "$Base$Path"; Headers = $h; ContentType = "application/json" }
  if ($Body) { $args.Body = ($Body | ConvertTo-Json -Depth 8) }
  Invoke-RestMethod @args
}
```

**a) Create your user, then make the token belong to that user.**

```powershell
$user = Api POST /api/v1/users @{
  username = "dev1"; email = "dev1@example.com"; first_name = "Dev"; last_name = "One"
  password = "a-long-local-password"; platform_role = "owner"
}
$user.user_id
```

Put that id in `.env` as `LOCAL_DASHBOARD_JWT_USER_ID=<user_id>`, then run
`python -m infrastructure connection-info` again and update `$env:TOKEN`.

**b) Register the provider and model.** `provider_name` and `model_name` must also exist in
`config/providers/<provider>.yaml` (for example `openai` / `gpt-4o-mini`), because routing
validates against that catalog.

```powershell
$provider = Api POST /api/v1/providers @{
  provider_name = "openai"; display_name = "OpenAI"; supported_operations = @("chat", "embed")
}
$model = Api POST "/api/v1/providers/$($provider.provider_id)/models" @{
  model_name = "gpt-4o-mini"; supported_operations = @("chat")
}
```

**c) Create a tenant and add your user to it.**

```powershell
$tenant = Api POST /api/v1/tenants @{ tenant_name = "Acme"; tenant_slug = "acme" }
Api POST "/api/v1/tenants/$($tenant.tenant_id)/members" @{
  user_id = $user.user_id; tenant_role = "developer"
}
```

**d) Create a deployment with the provider credential.** The key is written to Vault, and
only a reference is stored in the database.

```powershell
$dep = Api POST "/api/v1/tenants/$($tenant.tenant_id)/deployments" @{
  provider_id = $provider.provider_id; model_id = $model.model_id
  deployment_key = "chat-default"; deployment_name = "Default chat"
  api_endpoint_url = "https://api.openai.com/v1"
  credential = @{ auth_mode = "bearer_token"; api_key = "<YOUR_OPENAI_API_KEY>" }
  token_capacity_limit = 100000
}
```

**e) Grant the user an entitlement.** Omit `credential` to reuse the deployment's.

```powershell
Api POST "/api/v1/users/$($user.user_id)/entitlements" @{
  tenant_id = $tenant.tenant_id; deployment_key = "chat-default"
  provider_id = $provider.provider_id; model_id = $model.model_id
  entitlement_name = "dev1-chat"; api_endpoint_url = "https://api.openai.com/v1"
}
```

**f) Call the model.**

```powershell
Api POST /api/v1/llm/chat @{ messages = @(@{ role = "user"; content = "Say hello" }) } @{
  "X-Tenant-ID" = $tenant.tenant_id; "X-Deployment-Key" = "chat-default"
}
```

Set `"stream": true` in the body to receive a Server-Sent Events stream instead of JSON.
Endpoint reference: [app/api/api-endpoints-reference.md](app/api/api-endpoints-reference.md).

## 6. Start the token manager (required for inference)

Every inference call reserves capacity from the sibling `llm_token_manager` service
(`TOKEN_MANAGER_BASE_URL`, default `http://llm_tm_api:8000`). Without it, chat, embed and
rerank fail with `Token manager is unreachable.`; management endpoints still work. It has no
database of its own and joins the `llm_services_llm_net` Docker network created in step 3, so
start this project first.

**a) Make its `.env` match this project's.** In `../llm_token_manager/.env` these must equal the
values in `llm_services/.env`, otherwise the token manager rejects llm_services' internal
tokens (`Token manager rejected service authentication`):

| `llm_token_manager/.env` | must equal `llm_services/.env` |
|---|---|
| `DATABASE_USER`, `DATABASE_PASSWORD`, `DATABASE_NAME` | `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` |
| `JWT_SECRET_KEY` | `JWT_SECRET_KEY` |

The JWT secret is random per machine, so copy it rather than retyping it. Run from the
repository root (the folder containing both projects):

```powershell
@'
import pathlib, re
secret = re.search(r"(?m)^JWT_SECRET_KEY=(.*)$", pathlib.Path("llm_services/.env").read_text(encoding="utf-8")).group(1).strip()
p = pathlib.Path("llm_token_manager/.env")
p.write_text(re.sub(r"(?m)^JWT_SECRET_KEY=.*$", lambda m: "JWT_SECRET_KEY=" + secret, p.read_text(encoding="utf-8")), encoding="utf-8")
'@ | python -
```

**b) Start it.**

```powershell
cd llm_token_manager
.\infra\scripts\infra.ps1 doctor    # preflight; every line should say [ok]
.\infra\scripts\infra.ps1 up        # builds and starts the api, queue consumer, pgbouncer, redis, rabbitmq
```

Linux/macOS: `sh infra/scripts/infra.sh doctor` then `sh infra/scripts/infra.sh up`.
Details are in `../llm_token_manager/infra/README.md`.

**c) Verify that llm_services can reach it.**

```powershell
docker ps --filter name=llm_tm            # llm_tm_api should be "healthy"
docker exec -i llm_app python -c "import httpx; print(httpx.get('http://llm_tm_api:8000/api/v1/health/').status_code)"   # expect 200
```

Then make a real chat call (step 5f) or use the dashboard Playground. In the token manager logs
(`docker logs llm_tm_api --tail 20`) a successful call shows an acquire followed by a release.

## Running the API on the host (optional, for debugging)

Stop the container so port 8000 is free, then run uvicorn from the project venv:

```powershell
docker stop llm_app
.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --reload --port 8000
```

Host mode reads only `.env`, so it needs values the container gets from `docker-compose.yml`:

- `ENCRYPTION_MASTER_KEY` must be set in `.env` (step 2). It has no default, and uvicorn fails at
  startup with `encryption_master_key Field required` without it.
- `DATABASE_URL`, `REDIS_URL` and `VAULT_ADDR` must use `localhost`. `connection-info` prints
  ready-to-copy values.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `connection-info`: `missing keys: JWT_ISSUER, JWT_AUDIENCE` | Run `python -m infrastructure init`. |
| 401 `Token is invalid or has expired` right after minting a token | The API container is running an old image, or its `JWT_ISSUER`/`JWT_AUDIENCE` differ from the token's. Run `docker compose up -d --build app`, mint a new token, and check `docker logs llm_app --tail 20`. |
| 401 `Token format is invalid` | Token lifetime exceeds `JWT_MAX_TOKEN_AGE_SECONDS`. Set `JWT_ACCESS_TOKEN_EXPIRE_HOURS=1`. |
| uvicorn fails with `encryption_master_key Field required` | Host mode only. `.env` has no `ENCRYPTION_MASTER_KEY`. Do step 2. |
| `address already in use` on 8000 | The `llm_app` container owns it. Run `docker stop llm_app` or use the container instead. |
| Foreign key error when creating a deployment or entitlement | The token's user id does not exist in the `users` table. Do step 5a. |
| 403 on an inference call | The user has no active tenant membership with role `developer` or higher, or no matching entitlement. |
| `Token manager is unreachable.` on chat/embed/rerank | The token manager containers are not running. Do step 6 and check `docker ps --filter name=llm_tm`. |
| `Token manager rejected service authentication` | `JWT_SECRET_KEY` differs between the two `.env` files (step 6a). |
| `Provider config not loaded` | The provider has no `config/providers/<name>.yaml`, or the file's `provider_name` does not match its filename. |

## Project layout

```
app/
  api/                 HTTP routers, dependencies, exception handlers, request middleware
  auth/                JWT validation, role guards, tenant/inference authorization + grant cache
  clients/             token-manager HTTP client
  core/                settings (env + YAML), logging, typed exceptions
  database/            PostgreSQL persistence classes and SQL constants
  inference_routing/   authorized entitlement -> execution route
  providers/           provider adapters, circuit breakers, provider registry
  services/            business logic for management and inference
config/                base.yaml, environments/, providers/*.yaml, cloud_providers/
postgres_schema/       ordered SQL schema (see schema_creation_order.md)
infrastructure/        local stack control plane (python -m infrastructure ...)
documents/             architecture notes and the technical bible
```
